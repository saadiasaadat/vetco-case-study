The problem

Webinar follow-ups are slow, generic and, in animal health, risky

Slow

Someone reads every attendee record, decides who is ready to buy, writes an email and logs it by hand. Interested vets wait days for a reply.

Generic

To save time, everyone gets the same "thanks for attending" email, whether they asked for pricing or never turned up.

Risky

An attendee question can describe a suspected side effect. That must go to pharmacovigilance, not get a cheerful automated reply.

The workflow

The AI drafts; a person decides

Design decisions

Where the AI is allowed to act, and where it isn't

Four categories, one is a stop sign

Claude classifies each attendee as hot, warm, cold or needs_human. Any mention of a side effect, harm to an animal, a complaint or a data request is needs_human, and no draft is written.

No invented facts

The prompt forbids prices, dosages and clinical claims. When a question needs them, the draft says the team will follow up with the details.

Structured output

The agent returns JSON (category, confidence, reason, subject, draft), so routing is done by simple rules rather than by reading free text.

Approval before every send

Drafts arrive in the reviewer's inbox with Approve and Decline buttons. The workflow waits; declined drafts go nowhere.

Case 6 is the reason the approval step exists. The model read a competitor's questions as buying intent. A person caught it before any commercially sensitive reply went out.

What I'd improve next

Next versions

  1. Competitor and commercial-request rule (v1.1). Route enquiries from organisations that aren't clinics, or that ask about suppliers or group terms, to needs_human, then re-run case 6.
  2. FAQ answers from approved documents (v2.0). Add a retrieval (RAG) step so the agent answers common questions only from an approved FAQ and consent policy, quoting its source.
  3. Automated evaluation. Move the test cases into n8n Evaluations and grow the set beyond six, so every prompt change is re-tested.
  4. Monitoring. An error workflow that alerts on failures, and time-saved tracking per run to report the hours returned to the team.
Built and tested as a portfolio project. VetCo, its webinar and all attendee data are fictional.
